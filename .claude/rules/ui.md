# 画面の作り

画面まわりは、次の表のファイルを1か所の元にして、ほかはそこから作る。部品を足したり名前を変えたりするときは、まずここを直す。元になるファイルが増えたら、この表も直す。

| 何を | どこに |
| --- | --- |
| 画面の要素の id と種類(起動時にまとめて取り、合わなければ止まる。`index.html` との突き合わせは単体テスト) | `src/ui/ids.ts` |
| コマンド(名前・ショートカット・使える条件)。メニューのキー表記・ツールチップ・ヘルプのキー一覧・キーの処理はここから作る | `src/ui/actions.ts` |
| 左のツールバーのツール(名前・キー・ヒント)。スマホの下のバーもアイコンと名前はここから | `src/ui/tools.ts` |
| 左のツールバーの、その場で効く操作のまとまり(ツールの下。まとまりと中の並びは上のメニューと同じ順) | `src/ui/actions.ts` の `NAV_ACTIONS` |
| 左のツールバーのボタンの一覧(設定で出す・隠すを選ぶ。ボタンの `data-nav` と同じ id) | `src/ui/actions.ts` の `TOOLBAR_ITEMS`(上の表から作る) |
| アイコン(PC とスマホで共通) | `src/ui/icons.ts` |
| マウス操作の書き方(マウスの絵)と、ヘルプの操作方法の一覧。ツールごとのヒントは `src/ui/tools.ts` の `hint` | `src/ui/mouseHint.ts` |
| ツール全体の設定の画面(右上の歯車。ツールオプションの欄の右端に「UIを隠す」と並べる。このブラウザに覚える設定) | `src/ui/settingsDialog.ts` |
| 項目の説明(「?」で開く。`data-help` に説明の id) | `src/ui/help.ts` |
| 開いている作業のタブ(PC はメニューバーの右、スマホは上の見出しから開く一覧) | `src/ui/docTabs.ts` |
| スマホのシートへ移す部品(`index.html` の `data-m-slot` と、移す先のタブ) | `src/ui/mobile.ts` の `MOBILE_SLOTS` |

## 説明の出し方

- 長い説明を画面に並べない。読みにくくなるため。
- 項目の説明は「?」のボタンで開く。ツールチップ(`title`)だけに頼らない。触って使う端末や読み上げでは届かないため。
- ボタンの文言は短くし、状態は見出しの横に短く出す。
- 上の欄のツールのヒントとヘルプの操作方法は、端的に書き、カッコの補足を付けない。マウスの操作は文字でなくマウスの絵(`mouseHint.ts`)で示す。Mac のキーの書き分け(⌘ など)は書かない。

## 置き場所

- 左のツールバーは最も押しやすいので、ツールのほかに、よく使う操作も置く。そのぶん、ツールとその場で効く操作を見た目で見分けられるようにする。
- 右パネルのタブは、効く範囲で分ける。1つのタブの中で範囲を混ぜない。
- PC とスマホで、設定の分け方を揃える。
- メニューバーの右側は作業のタブに使う。「UIを隠す」と設定の歯車は、その下のツールオプションの欄の右端に置く。
- 同じ切り替えを右パネルとツールオプションの欄に二重に置かない(前は「レイヤーの揺れ」「自動で揺らす」を欄の右端にも置いていたが外した)。レイヤーの揺れはレイヤー一覧の行のアイコン(押した行だけに効く)と右パネル、自動で揺らすは左のツールバーの「アニメ」・アニメーションのメニュー・右パネルで切り替える。
- 上のメニューの「ツール」(`#toolMenu`)は、左のツールバーと同じ `src/ui/tools.ts` の表から `actions.ts` が作る。手で項目を書かない。
- 条件によって使えないコマンドで、理由を言わないと分かりにくいもの(タブが上限のときの開く系など)は、表の `blocked` に理由を書く。ショートカットで押したときに知らせ、左のツールバーのボタンのツールチップに足す。メニューやダイアログには `data-blocked="<コマンド名>"` の注意書き(`.menu-note`)を置くと、使えない間だけ理由を出す。
- メニューの中のまとまりの見出し(`menu-title`)は、押せる項目と見間違えないよう、罫線の区切りに小さく添える(`style.css`)。メニューの項目に、幅が変わる状態の文字(「選択中」など)を出さない。入・切は ✓ だけにする。
- アプリ全体に効き、作業中にすぐは触らない設定(このブラウザに覚えるもの)は、右上の歯車から開く設定画面(`#settingsDialog`、`src/ui/settingsDialog.ts`)に置く。右パネルには置かない。スマホでは上の「…」メニューから開く。
  - 例外: キーフレームの「重ねて表示」(経路・ゴースト・シークバー)の切り替えは、このブラウザに覚えるが、キーフレームを触りながらすぐ切り替えるので、キーフレームの部品の中に置く。経路・ゴーストは左のツールバーとメニューからも切り替えられ(状態は `App.keyOverlay`)、入れるとアニメーションのタブを開く(重ね表示はそのタブを開いている間だけ出るため)。

## スマホ

- スマホの部品は作り直さず、PC の DOM をシートへ移す。処理を PC と共通にするため。
- シートへ移す部品を DOM の並びで決めない。スマホで隠す部品を CSS の `:has()` で隠さない。

## 状態の変え方

- 同じ設定を複数の部品に出すときは、部品どうしで DOM を読んだりイベントを送ったりして同期しない。`App` のメソッド(`setLayerSwing` / `setAutoSwing` / `setPreset` など)を通し、モデルから表示を決める(Issue #45)。
- ショートカットは修飾キーまで含めて表に書く(`X` と `Shift+X` は別のキーとして扱われる)。
- Tab は「UIを隠す・戻す」に使う。キーボードで移ってきた部品(`:focus-visible`)にいるときと文字を打つ欄では、ふつうにフォーカスを移す(`actions.ts` の `keyboardFocus`)。Tab に別の役を足さない。
- 作業ごとの状態(プロジェクト・アンドゥ・ファイル名・未保存・選んだレイヤー・キーフレームの下書き・3面図のズームなど)は `App` の `Tab`(`src/app.ts`)に置き、`App` のゲッター・セッターから読み書きする。作業ごとの値を `App` に足すときは `Tab` に足す(足し忘れると、タブを切り替えても前のタブの値が残る)。ツール・ブラシ・表示の切り替えは全部のタブで共通。描画・物理・画面の部品は1つを使い回し、切り替えでは `Store.replace` と `History.take` / `restore` で中身を入れ替える。部品は `app.store` / `app.history` に購読したままでよい。
- 画面の状態(ツール・表示・ブラシ)を `App` から別のクラスへ分ける案は、変更が大きいわりに得るものが少ないので見送った(Issue #47)。新しい理由が無い限り、蒸し返さない。

# 画面の作り

画面の上では、UIを隠して3Dビューを画面いっぱいに出す機能(`toggleUi`、`src/ui/hideUi.ts`)を「全画面表示」と呼ぶ(Issue #156)。コードとこの文書の「UIを隠す」は同じもの。ブラウザの全画面は設定でオンにしたときだけ。

画面まわりは、次の表のファイルを1か所の元にして、ほかはそこから作る。部品を足したり名前を変えたりするときは、まずここを直す。元になるファイルが増えたら、この表も直す。

| 何を | どこに |
| --- | --- |
| 画面の要素の id と種類(起動時にまとめて取り、合わなければ止まる。`index.html` との突き合わせは単体テスト) | `src/ui/ids.ts` |
| コマンド(名前・ショートカット・使える条件)。メニューのキー表記・ツールチップ・ヘルプのキー一覧・キーの処理はここから作る | `src/ui/actions.ts` |
| 左のツールバーのツール(名前・キー・ヒント)。スマホの下のバーもアイコンと名前はここから | `src/ui/tools.ts` |
| 左のツールバーの、その場で効く操作のまとまり(ツールの下。まとまりと中の並びは上のメニューと同じ順) | `src/ui/actions.ts` の `NAV_ACTIONS` |
| 左のツールバーのボタンの一覧(設定で出す・隠すを選ぶ。ボタンの `data-nav` と同じ id) | `src/ui/actions.ts` の `TOOLBAR_ITEMS`(上の表から作る) |
| アイコン(PC とスマホで共通) | `src/ui/icons.ts` |
| マウス操作の書き方(マウスの絵)と、ヘルプの操作方法の一覧。ツールごとのヒントは `src/ui/tools.ts` の `hint` | `src/ui/mouseHint.ts` |
| ツール全体の設定の画面(右上の歯車。ツールオプションの欄の右端に「全画面表示」と並べる。このブラウザに覚える設定) | `src/ui/settingsDialog.ts` |
| 項目の説明(「?」で開く。`data-help` に説明の id) | `src/ui/help.ts` |
| 開いている作業のタブ(PC はメニューバーの右、スマホは上の見出しから開く一覧) | `src/ui/docTabs.ts` |
| スマホのシートへ移す部品(`index.html` の `data-m-slot` と、移す先のタブ) | `src/ui/mobile.ts` の `MOBILE_SLOTS` |
| スマホのシートの一番上の操作(左のツールバーの操作を横1列に。出さないものは `MOBILE_NAV_SKIP`。出す・隠すは左のツールバーと同じ設定で、映すのは `src/ui/settingsDialog.ts`) | `src/ui/actions.ts` の `NAV_ACTIONS` |

## 説明の出し方

- 長い説明を画面に並べない。読みにくくなるため。
- 項目の説明は「?」のボタンで開く。ツールチップ(`title`)だけに頼らない。触って使う端末や読み上げでは届かないため。
- ボタンの文言は短くし、状態は見出しの横に短く出す。
- 上の欄のツールのヒントとヘルプの操作方法は、端的に書き、カッコの補足を付けない。マウスの操作は文字でなくマウスの絵(`mouseHint.ts`)で示す。Mac のキーの書き分け(⌘ など)は書かない。

## 置き場所

- 左のツールバーは最も押しやすいので、ツールのほかに、よく使う操作も置く。そのぶん、ツールとその場で効く操作を見た目で見分けられるようにする。
- 右パネルのタブは、効く範囲で分ける。1つのタブの中で範囲を混ぜない。
- PC とスマホで、設定の分け方を揃える。
- メニューバーの右側は作業のタブに使う。「全画面表示」(UIを隠す、`toggleUi`)と設定の歯車は、その下のツールオプションの欄の右端に置く。
- 同じ切り替えを右パネルとツールオプションの欄に二重に置かない(前は「レイヤーの揺れ」「自動で揺らす」を欄の右端にも置いていたが外した)。レイヤーの揺れはレイヤー一覧の行のアイコン(押した行だけに効く)と右パネルで切り替える。
  - 例外: 特によく使う「アニメーションの再生・停止」と「自動で揺らす」は、欄の右端(全画面表示・設定の左、`#quickActs`)にアイコンだけで置く(スマホの上のバーと同じ組み合わせ。スマホの上のバーは、その隣に全画面表示 `#mFull` も置く)。左のツールバーの「アニメ」・アニメーションのメニュー・右パネルにもある。ここにほかの操作を足すときは、本当にいつも使うものかを確かめる(欄が狭い画面で折り返す)。
  - 例外: UIを隠している間は、右上のバー(`#viewBar`、`src/ui/hideUi.ts`)に、アニメーションの再生・停止(`toggleAnimation`)・自動で揺らす・お気に入りを選ぶ欄を「全画面を解除」(`#uiRestore`)と並べる。隠している間はほかの部品が見えないため。ボタンは `#quickActs` と同じくコマンドのボタンにし、`actions.ts` が絵と状態を入れる。
- アニメーション(再生する動き)は1つ(`project.take`)で、操作の記録とキーフレームはその作り方。右パネル・シートでは、1つの箱(`#animBox`)の上の帯に今の動きの印(◆ キーフレーム / ● 記録)と再生・カメラを戻す・消すを1つずつ置き、下に作り方を並べ、今の動きを作った側の枠を帯と同じ色にする(`ui/take.ts`)。共有していることは注意書きでなく、この並びで見せる。再生のボタンを作り方の側に置かない(作り方の側は「記録する」「登録する」だけ)。
  - キーフレームの一覧(下書き)は `project.keyframes` に置き、ファイルに保存する(記録した操作で今の動きを入れ替えても残る。Issue #145)。編集はアンドゥに積まないが、未保存にする。一覧を変えるのは、動きを差し替えるコマンド(`SetTake`)がキーフレームから作った動きに替えるとき(お気に入りの適用)だけで、アンドゥで前の一覧に戻す。操作の記録・消す・一覧から作ること(とそのアンドゥ)では一覧に触らない。
  - 再生のボタン・キーはどこでも同じ動き(`actions.ts` の `animationToggle`。`togglePlay`(L)・`toggleKeyPlay`(左のツールバー・`#quickActs`・スマホの上のバー。名前は隠すボタンの設定のために残す)・`toggleAnimation`(`#viewBar`)): 今の動きがキーフレームから作ったもの(か空)で一覧を再生できれば一覧から(直していれば作り直す)、記録した操作ならそれを再生する。
  - 3Dビューの下のバーにも同じ印を出す(`#playSrc`)。
- UIを隠している間の 3Dビューは見るだけにする(ツールを使わない。左ドラッグで平行移動・右で回す。`src/ui/input.ts` の `viewOnly`)。Player の `interaction: 'view'` と同じ操作にそろえる(Player の操作を変えるときは、こちらも見直す)。
- 上のメニューの「ツール」(`#toolMenu`)は、左のツールバーと同じ `src/ui/tools.ts` の表から `actions.ts` が作る。手で項目を書かない。
- 条件によって使えないコマンドで、理由を言わないと分かりにくいもの(タブが上限のときの開く系など)は、表の `blocked` に理由を書く。ショートカットで押したときに知らせ、左のツールバーのボタンのツールチップに足す。メニューやダイアログには `data-blocked="<コマンド名>"` の注意書き(`.menu-note`)を置くと、使えない間だけ理由を出す。
- メニューの中のまとまりの見出し(`menu-title`)は、押せる項目と見間違えないよう、罫線の区切りに小さく添える(`style.css`)。メニューの項目に、幅が変わる状態の文字(「選択中」など)を出さない。入・切は ✓ だけにする。
- アプリ全体に効き、作業中にすぐは触らない設定(このブラウザに覚えるもの)は、右上の歯車から開く設定画面(`#settingsDialog`、`src/ui/settingsDialog.ts`)に置く。右パネルには置かない。スマホでは上の「…」メニューから開く。
  - 例外: キーフレームの「重ねて表示」(経路・ゴースト・シークバー)の切り替えは、このブラウザに覚えるが、キーフレームを触りながらすぐ切り替えるので、キーフレームの部品の中に置く。経路・ゴーストは左のツールバーとメニューからも切り替えられ(状態は `App.keyOverlay`)、入れるとアニメーションのタブを開く(重ね表示はそのタブを開いている間だけ出るため)。

## 埋め込みモード

- 埋め込みモード(Issue #146、`App.embedded`。html に `embed`)で使わないコマンドは、`actions.ts` の表に `noEmbed: true` を付ける。使えなくし、ヘルプのキー一覧から外し、`data-cmd` の部品(メニューの項目は `<li>` ごと)に `data-embed-off` を付けて隠す(`style.css`)。左のツールバー・スマホのシートの一番上では、設定で隠したボタンと同じに扱い(中が全部隠れたまとまりの枠も隠れる)、設定の出す・隠すの一覧にも出さない(`settingsDialog.ts`)。コマンドでない部品(タブの閉じるボタン・タブの一覧の「開く…」)は `style.css` の `html.embed` で隠し、中身が無くなるメニューの見出しには `index.html` で `data-embed-off` を付ける。
- 埋め込み元へ戻るボタンは、PC はメニューバーの左端(`#embedBack`)、スマホは上のバーの左端(`#mBack`)。戻り先を受け取ったときだけ出す(`ui/embedSession.ts`)。

## スマホ

- スマホの部品は作り直さず、PC の DOM をシートへ移す。処理を PC と共通にするため。
- シートへ移す部品を DOM の並びで決めない。スマホで隠す部品を CSS の `:has()` で隠さない。
- 指で触ったスライダーは(スマホの配置ではいつも、PC の配置では指で触っている間)、ブラウザに触らせず `src/ui/touchSlider.ts` が動かす(横に引いた分だけ。縦はスクロール。html に `touch-sliders`)。スライダーを足すときは、`input` と `change` で受ければそのまま動く。スライダーの親(入れ物)は、指の横の動きを受けるので `touch-action: pan-y` になる。

## 状態の変え方

- 同じ設定を複数の部品に出すときは、部品どうしで DOM を読んだりイベントを送ったりして同期しない。`App` のメソッド(`setLayerSwing` / `setAutoSwing` / `setPreset` など)を通し、モデルから表示を決める(Issue #45)。
- ショートカットは修飾キーまで含めて表に書く(`X` と `Shift+X` は別のキーとして扱われる)。
- Tab は「全画面表示」(UIを隠す・戻す)に使う。キーボードで移ってきた部品(`:focus-visible`)にいるときと文字を打つ欄では、ふつうにフォーカスを移す(`actions.ts` の `keyboardFocus`)。Tab に別の役を足さない。
- 作業ごとの状態(プロジェクト・アンドゥ・ファイル名・未保存・選んだレイヤー・3面図のズームなど)は `Tab`(`src/app/tab.ts`)に置き、`App` のゲッター・セッターから読み書きする。`src/app` / `src/playback` の部品は作業ごとの値を自分で持たず、`App` から(ゲッター付きの小さなインターフェースで)今のタブの値を読む(例外は、画像全体のずれ(`StageSwing` の `base`)・記録中の操作(`TakeRecording`)・プレビューの途中の状態。部品が持つが、どれもタブの切り替えで捨てるか、作業中は切り替えを止める(`busy`)一時的な状態)。作業ごとの値を `App` に足すときは `Tab` に足す(足し忘れると、タブを切り替えても前のタブの値が残る)。ツール・ブラシ・表示の切り替えは全部のタブで共通。描画・物理・画面の部品は1つを使い回し、切り替えでは `Store.replace` と `History.take` / `restore` で中身を入れ替える。部品は `app.store` / `app.history` に購読したままでよい。
- 画面の部品が使うのは `App` だけにする。`App` の中身は `src/playback`(再生のつなぎ)と `src/app`(編集アプリだけの部品)へ委ねてあるが、部品からそこを直接呼ばない。イベント(`take` / `inflate` / `blur` など)は `App` が出す。記録のループ再生の状態は今も `Tab` に置かず、タブを切り替えると捨てる。
- 画面の状態(ツール・表示・ブラシ)を `App` から別のクラスへ分ける案は、変更が大きいわりに得るものが少ないので見送った(Issue #47)。新しい理由が無い限り、蒸し返さない。

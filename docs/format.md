# `.pukupop` ファイルの形式

PukuPop が保存する `.pukupop` ファイルの中身の説明です。`.pukupop` を自分のプログラムで読む人・確かめる人(埋め込み先の開発者、サーバー側でファイルを検査する人など)に向けて書いています。

ここに書いてあるのは、今の実装(`src/storage/popstage.ts`)がどう書き、どう読むかです。各表の「読むとき」の列や「読むときの上限」など、編集アプリが書かない形のファイルをどう扱うかは今の実装の扱いで、これから変わることがあります。先々まで約束するのは「版と互換」に書いたことだけです。

## 全体

- `.pukupop` は **ZIP ファイル**です。中に `project.json`(説明)、元画像、ウェイトマップ(PNG)、操作の記録(JSON)、サムネイル(PNG)が入ります。
- 拡張子は `.pukupop`。改名前のアプリ(PopStage)が保存したファイルは `.popstage` で、中身は同じ形式です(`project.json` の `app` が `"PopStage"` になっているだけ)。編集アプリはどちらの拡張子も開け、保存するときは `.pukupop` にします。読むプログラムは拡張子に頼らず、中身で判断してください。
- 今の形式の版(`formatVersion`)は **1** です(「版と互換」)。

### ZIP の条件

編集アプリが書く ZIP は次のとおりです。

| 項目 | 内容 |
| --- | --- |
| 圧縮の方式 | 無圧縮(stored、方式 0)と deflate(方式 8)だけ。今は `project.json` と記録(`motion/*.json`)を deflate、画像・ウェイトマップ・サムネイルを無圧縮で入れる |
| ZIP64 | 使わない(4 GB を超えるファイルは書けない) |
| 暗号化・分割 | 使わない |
| フォルダのエントリ | 書かない(`images/` などはパスの一部としてだけ現れる) |
| パスの文字 | 編集アプリが書くパスは ASCII だけ。ASCII 以外を含む名前には UTF-8 のフラグ(bit 11)を立てる |
| エントリの並び | 決まっていない。読む側は名前で探す |

編集アプリは同じ名前のエントリを重ねて書きません。重なっているファイルの扱いは「検査する側への注意」にあります。

### 中のパス

| パス | 必ずあるか | 中身 |
| --- | --- | --- |
| `project.json` | 必ずある | 説明(UTF-8 の JSON)。無いと読めない |
| `images/doc-N.<ext>` | 必ずある | 元画像。N はドキュメントの番号(0 から)。`<ext>` は `png`・`jpg`・`webp` のどれか。読み込んだ画像のバイト列をそのまま入れる(作り直さない) |
| `weights/doc-N-layer-M.png` | 編集アプリはレイヤーごとに1つ書く(無くても読める) | レイヤー M(0 から)のウェイトマップ。8 ビットのグレースケール PNG。無ければ何も塗っていないレイヤーとして読む |
| `motion/take.json` | 無いこともある | 操作の記録(ループ再生する動き)。記録が無ければ入れない |
| `motion/favorite-N.json` | 無いこともある | お気に入りだけが持つ記録。今の記録(`motion/take.json`)と同じ記録を持つお気に入りは、そちらを指す |
| `thumbnail.png` | 無いこともある | 一覧用の縮小画像。描くのに失敗したときは入れない |

- 読む側が使うパスは、`project.json` に書かれたもの(`documents[].image.path`、`documents[].layers[].weights.path`、`project.favorites[].take`)です。上の名前の付け方は編集アプリが書くときの決まりで、読むときはパスの形を決め打ちしないでください(例外は記録で、`motion/take.json` は決まった名前で読み、お気に入りの記録は `motion/take.json` か `motion/favorite-<数字1〜3桁>.json` の形のものだけを読む)。
- `motion/favorite-N.json` の N は、お気に入りの番号ではありません。書いた記録の通し番号です(`motion/take.json` があればそれを 0 番と数えるので、そのときは 1 から始まる)。
- 編集アプリが書くドキュメントは今は1つ(`doc-0`)です。形式としては複数持て、読み込みは先頭から 8 個までを読みますが、編集アプリと Player が表示するのは先頭(`documents[0]`)だけです。
- ドキュメントが1つも無いファイル(`documents` が空・配列でない・オブジェクトの要素が無い)は、読み込み自体は通りますが表示できません。編集アプリは「プロジェクトに画像が入っていません」と出して開かず、Player は `code` が `'invalid-file'` の `PlayerError` で失敗します。

以下の表は、`project.json` の項目をすべて挙げています。「読むとき」の列は、編集アプリと Player が値をどう読むか(無い・型が違う・範囲の外のとき)です。数の範囲の外の値は、範囲に丸めて読みます。

### いちばん外

| 項目 | 型 | 意味 | 読むとき |
| --- | --- | --- | --- |
| `formatVersion` | 整数 | 形式の版。今は `1`。書くときは必ず JSON の数にする | JSON の数で 1 以上の整数でなければ読めない(文字列の `"1"`・`true` なども読めない)。読むプログラムより大きければ読めない(「版と互換」) |
| `app` | 文字列 | 書いたアプリ。`"PukuPop"`(改名前のファイルは `"PopStage"`) | 読まない |
| `savedAt` | 文字列 | 保存した日時(ISO 8601、UTC) | 読まない |
| `project` | オブジェクト | 画像によらない設定(下) | 無ければ既定値で読む |
| `documents` | 配列 | ドキュメント(画像とレイヤー)。編集アプリが書くのは1つ | 配列でなければ空として読む。オブジェクトでない要素を除いてから、先頭の 8 個を読む。空なら表示できない(「中のパス」の下の注) |

### `project`

| 項目 | 型 | 意味 | 読むとき |
| --- | --- | --- | --- |
| `background` | 文字列 \| `null` | 背景色(`#rrggbb`)。`null` で透過 | `#` と16進6桁でなければ `null`(透過) |
| `camera` | 視点 | 主ビューの視点(下の「視点」) | 項目ごとに既定値で補う |
| `multiCamera` | 視点 | 3面図の「自由角度」の視点。後から足した項目で、古いファイルには無い | 無ければ既定値(`yaw` 0.7、`pitch` 0.45、`zoom` 1.5)。`roll` は常に 0 として読む |
| `fps` | 数 | 今は常に `60` | 読まない(常に 60) |
| `autoSwing` | 自動揺らし | ファイル全体の自動揺らし(下) | 項目ごとに既定値で補う |
| `keyframes` | 配列 | キーフレームの一覧(編集アプリの「キーフレーム」の並び)。記録(`motion/take.json`)を作る元で、記録を操作の記録で入れ替えても残る。各要素の形は記録の `keys` と同じ(「操作の記録」)。空でも書く。後から足した項目で、古いファイルには無い | 配列なら、記録の `keys` と同じく先頭の 12 個までを範囲に丸めて読む(1 個でも空でも、そのまま読む)。無い・配列でなければ、記録が `keys` を持つときはその写し、持たないときは空 |
| `favorites` | 配列 | お気に入り(下)。1つも無ければ項目ごと書かない | 無い・配列でなければ空。オブジェクトでない要素を除いてから、先頭の 30 個を読む |

#### 視点(`camera`・`multiCamera`・お気に入りの `camera`)

| 項目 | 型 | 意味 | 範囲・既定 |
| --- | --- | --- | --- |
| `fov` | 数 | 縦の画角(度) | 10〜90、既定 40 |
| `yaw` | 数 | 注視点のまわりの横の回転(ラジアン) | −1000〜1000、既定 −0.35 |
| `pitch` | 数 | 上下の回転(ラジアン) | −1.5〜1.5、既定 0.25 |
| `roll` | 数 | 視点の傾き(ラジアン。正で画像が画面上で時計回りに傾く)。後から足した項目 | −π 以上 π 未満に丸める。無ければ 0 |
| `zoom` | 数 | 注視点までの距離の倍率。**小さいほど近づいて大きく見える** | 0.05〜20、既定 1 |
| `target` | `{x, y, z}` | 注視点(元画像のピクセルを単位とする) | 各成分 −1000000〜1000000、無ければ 0 |

お気に入りの `camera` の既定値は、`fov`・`yaw`・`pitch`・`zoom` が(読み込んだ)`project.camera` の値、`roll` が 0、`target` が各成分 0 です。

#### 自動揺らし(`autoSwing`)

| 項目 | 型 | 意味 | 範囲・既定 |
| --- | --- | --- | --- |
| `enabled` | 真偽 | 記録が無いときに自動で揺らすか | `false` のときだけ切る(無ければ `true`) |
| `period` | 数 | 1回の揺らしの周期(秒) | 0.3〜10、既定 1.2 |
| `strength` | 数 | 強さ(0〜1) | 0〜1、既定 0.5 |

#### お気に入り(`favorites[]`)

揺れと動きの組み合わせを名前を付けて残したものです。画像とウェイトマップは持たず、レイヤーを `id` で指します。

| 項目 | 型 | 意味 | 読むとき |
| --- | --- | --- | --- |
| `id` | 文字列 | お気に入りの id | 空・重複なら振り直す |
| `name` | 文字列 | 名前 | 前後の空白を除き、40 文字(UTF-16 の単位で数える)までに切る。文字列でない・空なら「お気に入り N」 |
| `createdAt` | 文字列 | 作った日時(ISO 8601) | 日時として読めなければ 1970-01-01T00:00:00.000Z |
| `layers` | 配列 | レイヤーごとの設定。各要素は `{ id, pop, blend, physics }`(意味はレイヤーの同じ名前の項目) | 先に先頭の 8 個に切り、その中からオブジェクトでない要素・`id` が空か文字列でない要素を捨てる(なので 8 個より少なくなることがある)。読み込みでレイヤーの `id` を振り直したときは新しい `id` に合わせ、それ以外は `id` を 64 文字に切る。その結果 `id` が前の要素と重なる要素は捨てる。今のレイヤーに無い `id` の分も残す |
| `autoSwing` | 自動揺らし | このお気に入りの自動揺らし | `project.autoSwing` と同じ |
| `camera` | 視点 | このお気に入りの視点 | 上の「視点」 |
| `take` | 文字列 \| `null` | このお気に入りが持つ記録のパス。記録が無ければ `null` | `motion/take.json` か `motion/favorite-<数字1〜3桁>.json` の形のものだけ読む。読めなければ記録なし |
| `playing` | 真偽 | 当てたときに記録をループ再生するか | 記録が読めたときだけ `true` |

### `documents[]`

| 項目 | 型 | 意味 | 読むとき |
| --- | --- | --- | --- |
| `id` | 文字列 | ドキュメントの id | 空・重複なら振り直す |
| `name` | 文字列 | 名前(開いた画像のファイル名など) | 文字列でなければ「画像」 |
| `image` | オブジェクト | 元画像(下) | 画像のファイルが無ければ読めない |
| `position` | `{x, y, z}` | 位置 | 各成分 −1000000〜1000000、無ければ 0 |
| `rotation` | `{x, y, z}` | 回転(ラジアン) | 同上 |
| `scale` | 数 | 拡大率 | 0.01〜100、既定 1 |
| `meshDensity` | 整数 | メッシュの細かさ(長い辺の分割数) | 16〜512、既定 128 |
| `opacity` | 数 | 不透明度 | 0〜1、既定 1 |
| `layers` | 配列 | レイヤー(下)。一覧の下から順 | 配列でなければ空として読む。オブジェクトでない要素を除いてから、先頭の 8 個を読む。1つも無ければ空のレイヤーを1つ足す |

#### `documents[].image`(元画像)

| 項目 | 型 | 意味 | 読むとき |
| --- | --- | --- | --- |
| `path` | 文字列 | ZIP の中の元画像のパス(`images/doc-N.<ext>`) | `image` が無い・`path` が文字列でない・このパスのエントリが無ければ読めない。パスの拡張子は見ない(種類は下の `mime` の行のとおりに決める) |
| `mime` | 文字列 | 画像の種類。`image/png`・`image/jpeg`・`image/webp` のどれか | 種類は画像の中身(先頭のバイト)から決め、この値は使わない。中身から分からないときだけこの値を使い、3つのどれでもなければ `image/png` とする。保存し直すと、こうして決めた種類と、それに合う拡張子(`png`・`jpg`・`webp`)のパスで書く |
| `width` | 整数 | 元画像の幅(ピクセル) | 整数に丸め、32768 を超えれば 32768 にする。`width`・`height` のどちらかが無い・数でない・丸めて 1 未満なら、両方とも画像のヘッダの寸法(JPEG は EXIF の向きを当てたもの。「元画像のパスと寸法の読み方」)で補い(これも 32768 を超えれば 32768 にする)、ヘッダからも読めない・ヘッダの寸法が 0 なら読めない。**両方とも正しい値なら、画像の中身とは照らし合わせない** |
| `height` | 整数 | 元画像の高さ(ピクセル) | 同上 |

#### `documents[].layers[]`

| 項目 | 型 | 意味 | 読むとき |
| --- | --- | --- | --- |
| `id` | 文字列 | レイヤーの id(お気に入りと記録の `gainSets` から指される) | 空・重複なら振り直す(お気に入りの `layers[].id` と、記録の `gainSets` の id も合わせる。重複していた id は、先に出てきたレイヤーを指すとみなす。空の id はどのレイヤーも指さない) |
| `name` | 文字列 | 名前 | 文字列でなければ「レイヤーN」 |
| `visible` | 真偽 | 表示するか | `false` のときだけ隠す |
| `pop` | 数 | ポップ量(ウェイト 255 の所を手前へ持ち上げる高さ。元画像のピクセル単位) | 0〜1500、既定 80 |
| `blend` | 文字列 | 重ね方。`"add"`(下のレイヤーの高さに足す)か `"max"`(高い方を使う)。後から足した項目 | 無い・知らない値は `"add"` |
| `physics` | 揺れ | 揺れの設定(下) | 項目ごとに既定値で補う |
| `effect` | エフェクト | 膨らんだ瞬間のエフェクトの設定(下)。後から足した項目 | 無いときは切ってあるものとして読む。項目ごとに既定値で補う |
| `weights` | オブジェクト | `{ path, width, height }`。ウェイトマップの PNG のパスと大きさ | `path` だけを読む(「ウェイトマップ」)。エントリが無ければ何も塗っていないレイヤーとして読む。エントリがあって PNG として読めなければ、**ファイル全体を読めない** |

#### 揺れ(`physics`)

| 項目 | 型 | 意味 | 読むとき |
| --- | --- | --- | --- |
| `enabled` | 真偽 | 揺らすか | `false` のときだけ切る |
| `preset` | 文字列 | 選んだプリセット。`puru`・`bain`・`poyo`・`zun`・`buru`・`fuwa`・`yura`・`furi`・`guru`・`doki`・`tame`・`puku`・`puu`・`biyo`・`pofu`・`pon`・`custom` | 知らない値は `custom` |
| `hardness` | 数 | 硬さ(0〜1 の正規化値) | 0〜1、既定 0.6 |
| `mass` | 数 | 質量(0〜1) | 0〜1、既定 0.04 |
| `weight` | 数 | 重さ(重力の効き。0〜1) | 0〜1、既定 0.15 |
| `damping` | 数 | おさまり(減衰。0〜1) | 0〜1、既定 0.13 |
| `motion` | 文字列 | 揺らし方。`jiggle`・`jump`・`bounce`・`piston`・`shiver`・`float`・`sway`・`shake`・`circle`・`heartbeat`・`charge2`(ためて膨らむ)・`swell`(ゆっくり膨らむ)・`stretch`・`puff`・`pulse`・`none`。後から足した項目 | 無い・知らない値は、プリセットの揺らし方(`custom` なら `shake`)。このとき、プリセットが `tame`(ためてぼよん)なら、`motionParams` に無ければ `charge2.spread` を 0 にする(前と同じ動きにするため。ほかのプリセットの固有設定は補わない)。前の版の `charge`(統合した前の「ためて膨らむ」)は `charge2` として読み、`charge.depth`・`charge.time`・`charge.bulge` を `charge2.` の同じ項目へ移し(`charge2.` の同じ項目は、`charge.` の値か、無ければ既定値にする)、`charge2.spread` を 0 にする(前と同じ動き) |
| `motionParams` | オブジェクト | 揺らし方ごとの細かい設定。キーは `揺らし方.項目`(例: `jump.height`)、値は数。書いていない項目は既定値 | 知らないキー・数でない値は捨てる。範囲の外は丸め、選択式の項目は選択肢に無い値を捨てる。項目と範囲は `src/model/project.ts` の `MOTION_PARAMS` |

#### エフェクト(`effect`)

揺らし方を問わず(自動で揺らしても、手で揺らしても)、揺れの結果の手前への膨らみで出し、膨らんだ所(ウェイト)の半透明のコピーを外へ広げながら消します。膨らみの量(手前へのずれ ÷ ポップ量 + 広がり)が増え始めてから減り始めるまでを1回とし、1回につき1度だけ出します。前の回より弱い揺れ返しでは出ません。自動で揺らすとき、左右・上下にだけ動く揺らし方では出ません。

| 項目 | 型 | 意味 | 読むとき |
| --- | --- | --- | --- |
| `enabled` | 真偽 | エフェクトを出すか | `true` のときだけ出す |
| `ring` | 真偽 | コピーの輪郭(波紋)も同じ時刻・同じ大きさで出すか | `true` のときだけ出す |
| `timing` | 文字列 | 出すタイミング。`"burst"`(膨らみ始め。膨らむ勢いが `burstMin` と前の膨らみの勢い(時間とともに薄れる)の両方を越えた瞬間)か `"peak"`(一番膨らんだとき) | 無い・知らない値は `"burst"` |
| `burstMin` | 数 | `timing` が `"burst"` のときの出る勢いの下限(膨らみの量の1秒あたりの増え方)。小さいほど出やすい | 0.5〜12、既定 2 |
| `opacity` | 数 | 濃さ | 0.1〜1、既定 0.55 |
| `spread` | 数 | 消えるまでに広がる大きさ(ウェイトの重心からの距離に対する割合) | 0.05〜0.8、既定 0.3 |
| `duration` | 数 | 消えるまでの時間(秒) | 0.2〜1.5、既定 0.55 |
| `color` | 文字列 | 色。`"image"`(画像の色のまま)・`"white"`(白っぽく)・`"custom"`(`customColor` に寄せる) | 無い・知らない値は `"white"` |
| `customColor` | 文字列 | `color` が `"custom"` のときの色(`#rrggbb`) | `#` と16進数6桁でなければ `"#ff8ab8"`(小文字にそろえる) |
| `blend` | 文字列 | 重ね方。`"normal"`(ふつう)か `"add"`(加算) | 無い・知らない値は `"normal"` |

## 元画像のパスと寸法の読み方

一覧のサムネイルを自分で作る場合など、元画像を取り出すときは次の順に読みます。

1. ZIP から `project.json` を取り出して JSON として読む。
2. `formatVersion` が自分の知っている版以下かを確かめる(「版と互換」)。
3. `documents[0].image.path` が元画像のパスです。そのエントリを取り出せば、元画像のファイルそのもの(PNG・JPEG・WebP)が手に入ります。種類は `documents[0].image.mime` にも書かれていますが、中身と合っているとは限らないので、中身の先頭のバイトで判断してください(編集アプリと Player も中身から決めます)。
4. 幅と高さは `documents[0].image.width`・`height` から読みます。編集アプリが書いたファイルなら、**画像をデコードしなくても寸法が分かります。**

- `width`・`height` は、編集アプリが画像を開いたときに、ブラウザがデコードした結果の寸法です。PukuPop が表示に使う寸法(Player の `info.width`・`info.height` も)はこの値です。
- ただし、編集アプリと Player はこの値が正しい形なら画像の中身と照らし合わせません(無い・不正なときだけ、画像のヘッダの寸法で補います)。信用できないファイルでは、`project.json` の寸法をメモリの見積もりや画像の確かめの代わりに使わず、画像のヘッダも読んで確かめてください(「検査する側への注意」)。
- 画像のファイルのヘッダから寸法を読むこともできます(PNG の IHDR、JPEG の SOF、WebP の VP8/VP8L/VP8X)。ただし回転の情報(EXIF)を持つ画像(主に JPEG)では、ブラウザが回転を当てて読むと、ヘッダの寸法と縦横が入れ替わることがあります。PukuPop と同じ向き・寸法がほしいときは `project.json` の値を使ってください。編集アプリと Player は、`project.json` に寸法が無いときは、JPEG の EXIF の向き(Orientation)が 5〜8 なら縦横を入れ替えて補います(PNG・WebP の EXIF は見ません)。
- `thumbnail.png` は無いこともあり、大きさも小さい(下)ので、一覧の画像を確実に作るには元画像から作ってください。

Python で元画像と寸法を取り出す例(標準ライブラリだけ。読むときの上限の確かめは省いています):

```python
import json, zipfile

with zipfile.ZipFile("sample.pukupop") as z:
    project = json.loads(z.read("project.json"))
    version = project.get("formatVersion")
    # bool は int の仲間なので、isinstance ではなく type で数の型を確かめる
    if type(version) is not int or version < 1 or version > 1:
        raise ValueError("知らない版です")
    image = project["documents"][0]["image"]
    data = z.read(image["path"])  # 元画像のファイル(PNG / JPEG / WebP)
    # 種類は mime ではなく中身の先頭のバイトで見分ける
    if data[:4] == b"\x89PNG":
        kind = "png"
    elif data[:2] == b"\xff\xd8":
        kind = "jpeg"
    elif data[:4] == b"RIFF" and data[8:12] == b"WEBP":
        kind = "webp"
    else:
        kind = None
    print(kind, image["width"], image["height"], len(data))
```

## ウェイトマップ(`weights/doc-N-layer-M.png`)

塗った所(持ち上げる所)を表す、レイヤーごとの画像です。

| 項目 | 内容 |
| --- | --- |
| 色の形式 | 8 ビットのグレースケール(PNG の color type 0、bit depth 8)、インターレース無し。各行に Sub フィルタ |
| 値 | 1画素1バイト。0 が動かない、255 が最大(ポップ量の高さまで持ち上がる) |
| 並び | 行 0 が画像の上端。元画像と同じ向きで、元画像の全体を覆う |
| 解像度 | 元画像の長い辺が 1024 ピクセルを超えるときは、縦横比を保って長い辺を 1024 にした大きさ(各辺は四捨五入、最小 1)。1024 以下なら元画像と同じ大きさ |

解像度は元画像の寸法から次のように決まります(`src/model/weightmap.ts` の `weightSizeFor`)。

```
s = min(1, 1024 / max(width, height))
weightWidth  = max(1, round(width  * s))
weightHeight = max(1, round(height * s))
```

読むときの扱い:

- 読むのは `weights.path` だけで、`weights.width`・`height` は読みません。ウェイトマップの大きさは元画像の寸法から上の式で決め、PNG の大きさが違えば最近傍で引き伸ばして合わせます。
- 内蔵の読み込みが読めるのは、インターレース無しの、グレー・グレー+アルファ・RGB・RGBA(それぞれ 8・16 ビット)と、パレット(8 ビット)です(ほかのソフトで塗り直した PNG を戻せるように)。色のあるものは輝度(0.299R + 0.587G + 0.114B)にし、アルファは使いません。16 ビットは上位のバイトを使います。
- それ以外の PNG(1・2・4 ビット、16 ビット以外のビット深度のパレット、インターレースなど)は、ブラウザのデコードに任せます(色のあるものは同じ式で輝度にします)。
- 一辺が 4096 ピクセルを超える PNG は、どちらの読み込みでも読みません。
- `weights.path` のエントリがあって PNG として読めない(PNG でない、壊れている、大きすぎる、ブラウザでもデコードできない)ときは、そのレイヤーだけを捨てるのではなく、**ファイル全体を読めません**。エントリが無いときだけ、何も塗っていないレイヤーとして読みます。

## 操作の記録(`motion/take.json`・`motion/favorite-N.json`)

ループ再生する動き(視点・つかむ操作)を、物理の1刻み(1/120 秒)ごとに並べたものです。お気に入りが持つ記録も同じ形です。記録は `formatVersion` とは別に、自分の版 `version` を持ちます。

| 項目 | 型 | 意味 |
| --- | --- | --- |
| `version` | 数 | 記録の版。今は `1` |
| `dt` | 数 | 1件の時間(秒)。`1/120`(0.008333…) |
| `gainSets` | 配列 | つかむ操作がレイヤーごとにどれだけ効くかの組。各組は `[レイヤーの id, 0〜1]` の配列(読み込みでレイヤーの id を振り直したときは、新しい id に合わせる) |
| `samples` | 配列 | 1件ずつの数の並び(下) |
| `keys` | 配列 | キーフレームから作った記録なら、そのキーフレーム。無いこともある |

`samples` の1件は次の 15 個の数の並びです(古いファイルには最後の `roll` が無く、14 個です)。

| 位置 | 内容 | 読むとき |
| --- | --- | --- |
| 0〜2 | 視点の `yaw`・`pitch`・`zoom`(意味と範囲は「視点」と同じ) | 範囲に丸める。数でなければ `yaw`・`pitch` は 0、`zoom` は 1 |
| 3〜5 | 視点の注視点 `target` の x・y・z(元画像のピクセル単位) | 各成分 −1000000〜1000000。数でなければ 0 |
| 6〜8 | 物理に伝えた注視点の x・y・z。視点の注視点に、編集アプリの「揺らす」ツールで振った量を足したもの(3〜5 と同じく元画像のピクセル単位) | 同上 |
| 9〜11 | つかむ操作の量の x・y・z。ドラッグを始めた所からのポインタの動きを、ワールドの向きで表したもの。単位は「元画像の長い辺 = 2」とした長さ。つかんでいなければ `null` | 位置 9 が数のときだけ「つかんでいる」。各成分 −10〜10 に丸め、数でなければ 0 |
| 12 | `gainSets` の番号。無ければ −1 | 整数で、その番号の組があるときだけ使う |
| 13 | 1 ならこの刻みで視点を測り直す(視点のリセットなどで飛んだ所) | `1` のときだけ |
| 14 | 視点の `roll` | −π 以上 π 未満に丸める。無い・数でなければ 0 |

画角(`fov`)は記録しません(再生ではそのときのプロジェクトの画角を使います)。

`gainSets` の各組は `[レイヤーの id, 効き具合]` の並びです。読むときは、組の数を `samples` の件数まで、1組の要素を 8 個までにし、id が文字列でない・64 文字を超える・組の中で重なる要素を捨て、効き具合は 0〜1 に丸めます(数でなければ 1)。

`keys`(キーフレーム)の各要素は次の形です。読むときは先頭の 12 個までを読み、各項目を範囲に丸め(オブジェクトでない要素も捨てず、すべて既定の値のフレームとして読む)、2 個に満たなければ `keys` は無いものとします(記録そのものは残ります)。

| 項目 | 型 | 意味 | 範囲・既定 |
| --- | --- | --- | --- |
| `view` | オブジェクト | そのフレームの視点 `{ yaw, pitch, roll, zoom, target }`(意味は「視点」と同じ。`fov` は持たない) | `yaw` −1000〜1000(既定 0)、`pitch` −1.5〜1.5(既定 0)、`roll` −π 以上 π 未満(既定 0)、`zoom` 0.05〜20(既定 1.5)、`target` 各成分 −1000000〜1000000(既定 0) |
| `seconds` | 数 | 次のフレームまでの時間(秒)。最後のフレームは最初のフレームへ戻るまで | 0.1〜5、既定 1 |
| `mode` | 文字列 | `"smooth"`(なめらかに通り抜ける)か `"bounce"`(そのフレームで急に止まる) | `"bounce"` のほかは `"smooth"` |

読むときの扱い: 次のどれかなら、記録は**黙って捨て**、記録なしとして開きます(ファイル全体は開けます)。

- JSON として読めない、JSON のオブジェクトでない
- `version` が数の `1` でない
- `samples` が配列でない、件数が 60 秒分(7200 件)を超える、配列でない件・14 個に満たない件がある
- `dt` が数で、1/120 との差が 10⁻⁹ を超える(`dt` が無い・数でないときは確かめず、1/120 として読む)

そのうえで件数は 4 の倍数に切り捨て、0.5 秒(60 件)に満たなければ捨てます。

## サムネイル(`thumbnail.png`)

- 編集アプリがファイルに保存するとき、そのときの視点と背景で描いた縮小画像です。今は 320×240 ピクセルの PNG で書きます(背景が透過のときは透過のまま)。読む側は寸法を決め打ちせず、PNG のヘッダで確かめてください。
- 描くのに失敗したときは入れません。編集アプリ以外が作ったファイルにも無いことがあります。
- 編集アプリと Player は、ファイルを開くのにサムネイルを使いません。

## 読むときの上限

編集アプリと Player は、ZIP のエントリを展開する前に、**宣言されたサイズ**で次の上限を確かめます(`src/storage/popstage.ts` の `UNZIP_LIMITS`・`FAVORITE_TAKE_LIMIT`)。サイズは、ZIP に書かれた圧縮後のサイズと展開後のサイズの**大きい方**で数えます。1 MiB は 1048576 バイトです。

| 名前 | 対象 | 上限 | 超えたとき |
| --- | --- | --- | --- |
| `json` | `project.json` | 16 MiB(16777216 バイト) | 読めない |
| `image` | 元画像(1つあたり) | 256 MiB(268435456 バイト) | 読めない |
| `weights` | ウェイトマップの PNG(1つあたり) | 64 MiB(67108864 バイト) | 読めない |
| `take` | `motion/take.json` | 16 MiB(16777216 バイト) | 記録を捨てて開く |
| `FAVORITE_TAKE_LIMIT` | お気に入りだけが持つ記録(1つあたり) | 4 MiB(4194304 バイト) | その記録を捨てて開く |
| `thumbnail` | `thumbnail.png` | 8 MiB(8388608 バイト) | サムネイルを捨てて開く |
| `total` | 展開するエントリの合計 | 512 MiB(536870912 バイト) | 読めない |

- `total` に数えるのは、`project.json` を除いて、展開するエントリ(`project.json` に書かれた画像・ウェイトマップ・記録と、サムネイル)だけです。捨てたエントリは数えません。同じ名前のエントリが重なっていれば、すべてを数えます。
- 個数の上限もあります: ドキュメントは 8 個、レイヤーはドキュメントごとに 8 枚、お気に入りは 30 個まで読み、それより後ろは無いものとして扱います(そこから指されるファイルも展開しません)。どれも、オブジェクトでない要素を除いてから先頭の N 個を数えます。お気に入りの `layers` だけは逆で、先に先頭の 8 個に切ってから不正な要素を捨てます。
- 展開したあとにも確かめがあります。元画像は、ヘッダから寸法を読めないもの(PNG・JPEG・WebP でないもの)と、幅×高さが 1 億 2000 万画素を超えるものをデコードしません。ウェイトマップの PNG は一辺 4096 ピクセルまでです。

## 版と互換

- `formatVersion` は保存形式の版です。今は `1` で、まだ一度も上げていません。
- **古い版のファイルは読めます。** 公開した版で保存したファイルは、新しいアプリでも開けるように保ちます。項目が無いときは、上の表の既定値で読みます。版を上げるときは、古い版から順に今の形へ移す処理を足します。
- **項目を足すだけなら版を上げません。** 版を上げると古いプログラムで開けなくなるためです。今の形式にも、版を上げずに後から足した項目があります(`multiCamera`、`keyframes`、`favorites`、視点の `roll`、レイヤーの `blend`・`effect`、揺れの `motion`・`motionParams`、記録の `samples` の 15 個目)。版を上げるのは、作りを変えて古いプログラムが正しく読めなくなるときだけです。
- **知らない項目は読み飛ばします。** 古いプログラムでも、項目が足されただけのファイルは開けます。ただし、足された項目や、知らない値(新しいプリセット・揺らし方など)は使われず、既定の値として読むので、新しいアプリで見たときと見え方・揺れ方が違うことがあります。編集アプリで開いて保存し直すと、知らない項目は残りません。
- **読むプログラムより新しい版のファイル**(`formatVersion` がそのプログラムの版より大きい)は読めません。編集アプリは「このファイルは新しい版(N)で保存されています。アプリを更新してください。」と出して開きません。Player(`pukupop-player`)は `code` が `'unsupported-version'` の `PlayerError` で失敗します。
- 操作の記録(`motion/*.json`)の `version` は `formatVersion` とは別です。知らない `version` の記録は黙って捨てられ、ファイルは記録なしとして開きます。
- **保存形式の版と Player の版は別のものです。** Player の版(`pukupop-player` の `0.1.0` など)は Player の API の版で、保存形式の版が変わらなくても上がります。保存形式の版が上がると、それより前の Player では新しいファイルを `unsupported-version` で読めなくなるので、新しい Player を入れる必要があります。

自分で読むプログラムも、知らない `formatVersion`(今なら 2 以上)は断り、知らない項目は無視するのがおすすめです。

`formatVersion` は、書くときは必ず JSON の数(整数)にしてください。編集アプリと Player は、文字列の `"1"` などの数でない値を版として読まず、ファイルを開きません。自分で読むプログラムも、数の型であることを確かめるのがよいでしょう(上の Python の例のように)。

## 検査する側への注意

`.pukupop` は利用者が持ち込むファイルなので、信用できないものとして扱ってください。編集アプリと Player の読み方と、サーバー側で検査するときに勧める確かめを挙げます。編集アプリと Player が確かめていないこと(下の `image.width`・名前など)は、検査する側で確かめてください。

- **展開する前にサイズを確かめる。** 上の「読むときの上限」を、ZIP に書かれた宣言サイズ(圧縮後と展開後の大きい方)で確かめてから展開します。宣言サイズは偽れるので、展開するときも、出力が宣言サイズ(上限)を超えたら止めるようにしてください。
- **必要なエントリだけを、名前で探して展開する。** まず `project.json` だけを展開し、そこに書かれたパスと、決まった名前(`thumbnail.png`、`motion/take.json`)のエントリだけを展開します。ZIP の中の名前をそのままファイルシステムのパスに使わないでください(`../` などを含む名前で、展開先の外に書かれることがあります)。
- **ZIP は中央ディレクトリを正として読む。** 編集アプリと Player(ZIP の読み込みは fflate)は、末尾の中央ディレクトリからエントリの名前・圧縮の方式・サイズを読み、ローカルヘッダはデータの位置を求めるのにだけ使います。ZIP を先頭から流しながら読む場合も、ローカルヘッダの名前やサイズではなく中央ディレクトリの値で判断してください(ローカルヘッダと中央ディレクトリの食い違いや、中央ディレクトリに無いエントリで、検査したものと PukuPop が使うものが違ってしまうため)。
- **同じ名前のエントリが重なっていることがある。** 上限はすべてのエントリを数えて確かめます。今の実装(fflate 0.8.3)では、中央ディレクトリで後ろにあるものが使われますが、どれを使うかは ZIP のライブラリによって違います。検査したものと表示されるものが食い違いうるので、検査では同じ名前のエントリが重なったファイルを断るのを勧めます。
- **`project.json` の値を確かめる。** `formatVersion` は数の型の 1 以上の整数か、数は有限か・範囲の中か、文字列か、を見てから使います。オブジェクトのキーを調べるときは自分のプロパティだけを見ます(JavaScript なら `in` ではなく `Object.prototype.hasOwnProperty.call`。`constructor` などを拾わないように)。背景色は `#rrggbb` の形のものだけを使います。
- **個数を数える。** ドキュメント・レイヤー・お気に入りは上の個数まで読み、それより多い分は無視します。
- **画像はデコードする前に寸法を確かめる。** ヘッダの寸法で画素数を確かめてからデコードします。PNG は、ヘッダの寸法から決まる大きさより多くは展開しません。
- **`image.width`・`height` を信用しない。** 編集アプリと Player は、この値が正しい形なら画像の中身と照らし合わせずに表示に使います。信用できないファイルでは、この値をメモリの見積もりや画像の確かめの代わりに使わず、画像のヘッダの寸法も確かめてください。
- **`image.mime` を信用しない。** 書かれた値は画像の中身と合っているとは限りません(編集アプリと Player は中身から種類を決めて読みます)。取り出した元画像を配るときは、`mime` をそのまま Content-Type に使わず、中身(先頭のバイト)から種類を判断してください。
- **名前はどんな文字列でも入る。** `documents[].name`、レイヤーの `name`、お気に入りの `name` は、長さ(お気に入りの名前を除く)も中身も確かめていません。HTML に入れるときはエスケープしてください。
